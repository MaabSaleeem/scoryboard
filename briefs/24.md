## The findings that shape the collection

Four things were measured in step 1 that the map did not know, and each one
changes what an article says.

1. **The word filter is on the server, and it masks rather than refuses.**
   `POST /comments` with a swear word in it answers `200` and stores the word
   as asterisks, one per letter - `This is ****ing ****`. The same happens to
   `PUT /teams/:id` (name and bio), `PUT /users/:id` (bio), `POST /friends`
   (name) and `POST /chats/.../messages` (text). Nothing in the browser does it:
   the swept bundle carries no word list and no filter library. "Language
   filtering" in 24.4's title therefore means the profanity mask and nothing
   else - there is no shipped localisation and CLAUDE.md says not to document
   the footer's language picker. Mild words pass ("damn", "bloody hell"); the
   list itself is the server's and is not published.
2. **The upload limits are three different numbers depending on who is
   counting.** The page caption says "JPG, GIF or PNG. 3MB max." everywhere a
   photo can be chosen. The browser then re-encodes the crop to WebP and checks
   3MB. The comment composer and the match feed check 3MB for an image and
   **200MB for a video** in the browser before any request goes out. And the
   server has its own limits, measured by bisection with incompressible WebPs
   on 2026-09-04:

   | Upload | Server accepts | Refuses | Page says |
   |---|---|---|---|
   | `POST /players/avatar`, `POST /teams/avatar` | 66KB | **117KB** - so about 100KB | 3MB |
   | `POST /players/:id/banner`, `POST /teams/:id/banner` | 2.98MB | **3.10MB** - so 3MB | 3MB |
   | `POST /comments/media` | 1.92MB | **2.02MB** - so 2MB | 3 MB (the composer) |
   | `POST /comments/media`, 8MB | - | **500 Internal Server Error** | - |

   The refusal is `413 {"error":"File too large"}` and the composer prints
   those three words as they are. So a 2.5MB photo passes the composer's check,
   is posted, and comes back "File too large" - 24.2's third capture, and a
   ticket. The map's note "1MB avatars and logos" is a line in the bundle
   (`uploadImageFile`: 1MB for anything that is not a banner) that no live
   caller reaches: all three callers upload banners. The real avatar limit is
   the server's 100KB, which the cropper's WebP output normally stays under.
3. **A permission problem can look like a crash.** Opening the settings of a
   leaderboard you have no role on fetches its team list, gets
   `403 "Only leaderboard administrators can view teams in this leaderboard"`,
   and falls to the app's error boundary: **"This page couldn't load / Reload to
   try again, or go back."** on a bare white page. Collection 08 recorded this
   (briefs/08.md, 08.2) and 24.3 photographs it as the "Something went wrong"
   screen because it is the one that can be produced on demand. 24.1 tells the
   reader that this screen can mean "not your leaderboard".
4. **A team's settings page has a real Access Denied screen.** `/teams/:id/settings`
   for a team you neither own nor administer renders **"Access Denied / You are
   not allowed to edit this team. Only team owners and administrators can
   access team settings."** inside the normal frame, with no API write and no
   redirect. Collection 12 found the tournament equivalent is a silent redirect
   (briefs/12.md, open question 5); the team one is the only literal permission
   screen in the app, and it is 24.1's first capture.

### 24.1 You do not have permission to do that

- Persona: Marc (manager_free). Free. Administrator of KB 24 United; a
  stranger to everything else of Owen's.
- Preconditions found: a permission refusal takes four different shapes in the
  app and only one of them says "permission". The dummy-team notice does; the
  team settings page says Access Denied; the match page quietly changes its
  heading and drops the manager controls; a disabled button says nothing at
  all. And a fifth shape is a crash (24.3). Roles are per team - Owner,
  Administrator, Player - and per leaderboard, and there is no way to give
  yourself one: the Owner does it from Edit Team (07.7), and ownership cannot
  be transferred at all (config/api.md, "Teams").
- Dual capture: no. Roles, not plans.
- Steps (the article is a diagnosis, not a procedure - one list, four screens):
  1. Read the screen. If it says **Access Denied**, you opened a team's settings
     and you are not its Owner or an Administrator.
  2. If it says **DUMMY TEAM**, the team is somebody's practice opponent and
     only its owner can open it.
  3. If a button is greyed out on Edit Team, you are an Administrator and the
     button is the Owner's - Delete Team is the one.
  4. If a match page is headed **Match Preview (View Only)**, you are on
     neither team's staff and cannot run the match.
  5. Ask the Owner. Point them at 07.7.

### 24.2 Photo and file upload limits

- Persona: Marc for 01-03. Owen (Pro) for 04, because the match feed's Add
  media is the only place a video can be chosen and it is Pro-only (10.8).
- Preconditions found: see finding 2 above. The Profile settings card has two
  file inputs, both `accept="image/*"`; the comment composer's is `image/*`
  (multiple); the match feed's is `image/*,video/*` (multiple). The composer's
  message for a refused type is the server's `415 "Unsupported file type"`
  printed as "Unsupported file type". The match banner cropper checks 3MB and
  prints "Image size must be less than 1MB" - a copy defect in the bundle,
  recorded in `config/api.md`, not photographed (collection 09's screen).
- Dual capture: no. The Free gate on the feed's Add media is 10.8's.
- Steps:
  1. Read the caption under a picture control: "JPG, GIF or PNG. 3MB max." is
     what you may choose. Scoryboard converts it after you crop.
  2. On a comment, a file over 3 MB is refused before it is sent: "File exceeds
     3 MB: <file>".
  3. A file between 2 MB and 3 MB is sent and refused by the server: "File too
     large". Shrink it below 2 MB.
  4. On a match feed (Pro), a video over 200 MB is refused the same way: "File
     exceeds 200 MB: <file>".
